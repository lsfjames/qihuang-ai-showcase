# 岐黄向海

**AI 辅助的中医药文化跨文化表达协作原型** · [English](README.en.md)

围绕中医药文化概念面向海外青年的表达，连接模型草稿、人工修订、分角色审核、本站发布与理解反馈。工程重点是把 AI 接入**真实业务流程**，并为版本冲突、越权操作与演示数据隔离设置可测试的边界。

**核心源码保持私有。本仓库只提供项目说明与界面预览，无法直接启动网站，也不是线上托管演示。**

## 业务流程

文化主题与目标语言 → 真实模型草稿 → 人工修订 → 专业概念核对 → 跨文化表达审核 → 本站发布 → 反馈与前后复述记录。

- 文化解释围绕历史语境、词语含义与日常类比；模型草稿不等于专业结论。
- 青年主创负责选题、创意、取舍与改稿；AI 提供候选文本，来源仍需人工核对。
- 系统保存版本与审核记录。**账户具有审核角色，不等于该账号背后已获得专家资质认证**；演示账号的通过操作不构成真实专家意见。

## 已实现的工程能力

- **AI 接入**：服务端调用模型接口；配置不全时明确报错，不用模板冒充生成结果。
- **结构化草稿**：标题、正文、字面表达、语境解释及文化／来源／风险说明共七字段。Ollama 分支请求 JSON Schema，服务端再做结构校验——结构合规**不等于内容正确**。
- **调用追溯**：记录模型、提示词版本、请求标识、耗时与上游提供的 token 用量；上游未提供时明确标记缺失，**不做估算**。
- **版本控制**：编辑、审核、发布与反馈携带 `expectedVersion`；缺失或非法返回 400，过期返回 409；改稿递增版本并使既有审核失效。
- **权限**：JWT 登录与角色检查、私有资源所有权校验、字段白名单；工作台按同一版本两关审核后方可发布。旧内容模块另保留三关流程，**两套路径不可混为同一状态机**。
- **写入一致性**：业务变更与审计记录在同一事务内提交，落盘失败整体回滚并返回明确失败码，不会把失败当作成功。
- **理解体验**：自愿同意、首次复述、固定材料版本、再次复述、人工评阅入口与撤回。

## 模型调用实测

2026-10-17 在本机通过应用自身链路完成一次真实本地推理（Ollama / Qwen2.5:1.5b）：生成一篇关于"治未病"概念的英文草稿，耗时约 15.8 秒，上游报告 token 用量输入 701、输出 306，界面记录提示词版本与请求标识。

这只说明**调用链路可用**。它不说明模型输出准确、不说明文化表述已被专业审校，也不构成任何受众效果证据。
